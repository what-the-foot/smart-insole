# 11. 사람이 Codex 결과를 검토하는 방법

이 문서는 개발 경험이 많지 않은 프로젝트 담당자가 Codex의 작업 결과를 승인하기 전에 확인할 항목입니다.

## 1. 작업 시작 전에 확인

Codex의 첫 계획에서 다음 다섯 항목이 보여야 합니다.

- 작업 ID가 정확히 하나인가
- 목표가 작업 보드와 같은가
- 수정할 파일 범위가 좁고 구체적인가
- 계약 또는 DB migration 영향이 적혀 있는가
- 실행할 테스트 명령이 적혀 있는가

여러 작업을 한꺼번에 하겠다고 하면 다음 문구로 범위를 줄입니다.

```text
이번 실행에서는 작업 ID 하나만 수행하세요.
현재 ID와 직접 관련되지 않은 변경은 하지 말고 발견 사항으로만 보고하세요.
```

## 2. 구현 도중 중단해야 하는 신호

다음 상황이면 바로 수정 방향을 다시 지시합니다.

| 신호 | 문제 |
|---|---|
| 기존 프로젝트를 삭제하고 새로 생성 | 기존 코드·설정 손실 위험 |
| OpenAPI와 다른 DTO를 임의 생성 | 백엔드·프론트 계약 분기 |
| 테스트를 삭제하거나 skip | 오류를 숨길 위험 |
| 실제 secret을 파일에 작성 | 보안 사고 위험 |
| 100Hz 데이터를 JPA `save()` 반복 | DB 부하와 처리 지연 위험 |
| 원본 ADC 값을 정규화 값으로 덮어씀 | 재분석 불가능 |
| 질환을 확정하는 문구 | 프로젝트 범위와 안전 원칙 위반 |
| 요청하지 않은 commit/push | 검토 전 원격 변경 위험 |

교정 문구:

```text
현재 diff를 다시 검토하세요.
작업 ID 범위 밖 변경, 테스트 약화, 계약 불일치를 제거하고
필수 기능과 검증만 남기세요. 코드를 수정한 뒤 실제 테스트 결과를 다시 보고하세요.
```

## 3. 완료 보고에서 확인

### 구현

- 작업 ID의 완료 조건이 모두 구현되었는가
- 관련 없는 파일이 바뀌지 않았는가
- 새 라이브러리를 추가한 이유가 타당한가
- OpenAPI 또는 DB 변경이 문서에 적혀 있는가

### 테스트

“테스트를 작성했다”가 아니라 다음처럼 실제 결과가 있어야 합니다.

```text
./gradlew test → 성공, 42 tests
npm run test -- --run → 성공, 18 tests
npm run build → 성공
```

명령을 실행하지 못했다면 이유와 미검증 범위가 있어야 합니다. 실행하지 않은 테스트를 성공으로 취급하지 않습니다.

### Git diff

사람이 최소한 다음을 확인합니다.

```bash
git status --short
git diff --stat
git diff
```

확인 항목:

- secret 또는 개인정보
- 예상 밖 파일 삭제
- 대규모 자동 포맷
- 테스트 삭제
- 계약과 다른 필드명
- 의료 진단 문구
- TODO로 남긴 핵심 기능

## 4. 백엔드 핵심 확인

- 사용자 A가 사용자 B의 기기·세션·결과를 읽을 수 없는가
- Receiver API는 사용자 JWT와 별도 인증인가
- `(sessionId, deviceId, sequence)` 중복 저장이 막히는가
- 센서 원본은 JDBC batch로 저장되는가
- `deviceTimeMs`와 `sequence`로 분석 순서를 정하는가
- WebSocket 전송 실패가 원본 DB 저장을 취소하지 않는가
- Flyway가 빈 MySQL에서 적용되는가
- 6개와 8개 센서가 모두 처리되는가

## 5. 프론트엔드 핵심 확인

- 생성 타입을 직접 수정하지 않는가
- 로그인하지 않으면 보호 페이지에 들어갈 수 없는가
- 왼발과 오른발을 바꾸어 표시하지 않는가
- 한쪽 발이 끊겨도 다른 발 데이터가 유지되는가
- WebSocket 재연결 시 snapshot을 먼저 복구하는가
- 페이지 이동 후 구독과 polling이 남지 않는가
- 품질 상태를 색상만으로 표현하지 않는가
- 모바일에서 시작·종료·취소 버튼을 사용할 수 있는가

## 6. 승인 기준

다음이 모두 충족되면 해당 작업 ID를 완료로 승인합니다.

- 요구 기능 구현
- 정상·실패·경계 테스트
- test/lint/check/build 실제 성공
- 계약과 일치
- 관련 없는 diff 없음
- secret 없음
- 미검증 위험이 수용 가능
- 작업 보드에서 해당 ID 하나만 체크

하나라도 확인되지 않으면 작업 보드를 체크하지 않고 Codex에 해당 항목만 보완하도록 지시합니다.
